# VXSK Website — V19 integration report
**Scope:** VXSK Website working clone / Cloudflare test only. **Do not deploy to VXSK OFFICIAL yet.**
**Date:** 5 November 2026

## 1. What has been added

### Public rankings / My Account
- Responsive Top 10 panels on the homepage for **players, teams and staff**. A link appears in the homepage's MORE menu.
- Rankings are generated by protected Supabase functions from recorded activity, not client-side invented scores.
- Player points: **+10** per approved tournament participation; **+25** per confirmed tournament match win; **+5** per completed showmatch appearance. This is a proposed point policy, configurable in future updates.
- A completed showmatch currently counts for **participation only**. Existing showmatch records do not contain a reliable verified winner; no fictitious win points are assigned.
- Staff contribution: **+5** per reviewed application and **+10** per eligible audited tournament/team/result action. Duplicate work events are filtered by action/entity where possible.
- Team ranking sorts by **accepted member count first**, then aggregate member points, then name. A verified user can submit **one** team join request at a time; staff approval with MFA is required. Rejected applicants can leave/cancel their request and try later.
- My Account activity displays tournament participations, verified wins, showmatch appearances, personal points and staff points when applicable.
- Privacy: hidden/undiscoverable player profiles are excluded from the public player leaderboard; private game account IDs, email addresses and user IDs are not exposed through these widgets.

### Tournament formats and brackets (16–64)
- New format registry for **Single Elimination**, **Double Elimination**, **Groups**, **Swiss**, **Groups → Knockout**, **Swiss → Knockout**, **Play-In → Groups → Knockout**, and **Play-In → Swiss → Knockout**.
- Uses the EXISTING `vxsk_p12_tournaments` registry. No duplicate public tournament system has been created.
- Separate phase/fixture tables track rounds, lanes, group assignments, winner and loser results. Owners choose format and capacity (16–64) before generating. Starts with approved entrants only; existing scheduled/started brackets are protected against recreation.
- Odd entry counts use a BYE. Groups are distributed into 3–4 player groups with round-robin pairings. Swiss uses up to 5 rounds, pairing by record/differential with rematch avoidance where possible. Double elimination tracks zero-loss / one-loss pools and a possible grand-final reset.
- UI exposes stage details, scorecards, standings and responsive horizontally scrolling brackets. Advanced tournament controls live in a collapsible Staff Commands section to reduce clutter.
- Referee/reviewer with MFA can submit a result report. Owner with MFA can approve or reject it; Owner can record a verified score directly with a reason. Owner score edit/reset is audited and blocked after downstream rounds are generated.

### Staff record management
- Owner/MFA audited archive interface for **non-live official tournaments**, **legacy match fixtures**, and **public showmatch posts**. A snapshot and reason are retained. This is **soft archive/hide**, not permanent deletion.
- Other categories (private referee reports, challenges, marketplace applications/requests, server feedback and existing application deletion) retain their original workflows; universal deletion of private records is **not** implemented because this needs a separate dependency and retention audit.

### Performance / preservation
- New V19 assets are small plain CSS/JS, no new frontend framework, no new continuous network polling. Responsive layout and bracket overflow are scoped to their own containers.
- Existing VXSK website, friend/social features, VXSK AI bubble and Feedback features are retained from V18.
- No modifications to VXSK OFFICIAL repository or its production branch were made by this work.
- Existing Arab Cup tournament and 2 approved applicants retained. No fictitious accounts were added.

## 2. Verified in this build
- New RLS-protected SQL tables and RPCs applied in Supabase; anonymous EXECUTE to private format/score/team/record RPCs denied.
- Live public leaderboard RPC returned **3 players, 5 staff and 3 published teams** as of this QA run. Scores are sourced from current records, not screenshots or placeholders.
- Disposable database smoke tests in subtransactions: **16-team Groups produced 24 fixtures; Single, Swiss and Double created 8 opening fixtures each and advanced at least 4 next-round fixtures; Groups qualified 8 teams into a 4-match Knockout round.** Tests rolled back their data; 0 test phases and fixtures remain.
- JavaScript syntax checks passed for V19 assets.
- Browser-rendered mock UI QA completed at desktop and 390px mobile widths: rankings, My Account points, Bracket stages, Staff manager. No document-level horizontal overflow in those test layouts.
- ZIP contents and CRC checked at packaging.

## 3. Not yet verified / not production-ready
- **Full 16–64 user end-to-end lifecycle** using real Supabase sessions, referrals and actual score approvals is not tested. Only 2 approved player registrations currently exist.
- The custom Double/Swiss/Play-In engines are **test-stage implementations**, not proven equivalents to all professional esports rulebooks. Swiss rematch/tiebreak rules, group tie-breaks, double-elim reset and edge cases require full simulations and refinement before competitive use.
- A complete security audit is outstanding. Supabase security advisors still report legacy warnings concerning exposed SECURITY DEFINER functions and authentication settings, besides the audited new RPCs. An exposed RLS maintenance RPC `public.rls_auto_enable()` was restricted to prevent anonymous/authenticated invocation.
- No real Cloudflare browser testing was performed after the new V19 bundle was built. The ZIP is for the Cloudflare test Worker, **not the Official site**.
- Existing V18 Single Elimination for 2/4/8 registrants remains available; V19 advanced formats require **16–64 approved entrants** and are separate stage tables under the same event registry. Do not switch an event after a bracket is generated.
